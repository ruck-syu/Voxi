# Candidate 002: lossless literal binding before native inference

Candidate 001 failed useful recovery on the first independent bank: 0/4 supported
rule refusals were recovered, with no effective model additions. Its immutable
source/runtime snapshot and original frozen manifest are preserved. Bank 001 is
now inspected development evidence for any subsequent implementation, never an
untouched validation set again.

## New hypothesis

The unchanged tiny v3 checkpoint loses unfamiliar literal names. Bind those
values to collision-free, familiar lexical aliases before native inference, then
require exact alias multiplicity, argument roles, operation and constraints in
the parsed model output. Restore only source-authorized values into the typed
Intent. Do not infer or repair missing model slots, invented aliases or changed
roles. The native model must actually produce an acceptable structural rewrite;
the source contract alone must never authorize a fallback result.

A development probe showed that the model drops members of quoted comma lists,
but preserves the same familiar names joined by `and`. A lossless lexer may
normalize separators inside an independently verified folder-name list, preserving
the exact original values separately. It may not strip unsupported clauses or
replace an arbitrary request with its expected canonical output.

Keep the bounded domains and fail-closed policy: original rules win, typed hard
refusals remain terminal, unknown scheduling/extra actions remain rejected,
certified output still goes through the scheduler, planner, preview and
confirmation. The method must be explicit: this is host literal restoration,
not a claim that the raw model copied unfamiliar names correctly.

## Validation

evaluation. Review all effective additions and any accepted error. No training
