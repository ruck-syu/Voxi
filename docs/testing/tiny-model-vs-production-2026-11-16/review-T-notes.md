Reviewed the 100 T rows against the public README and `website/commands.html`. The JSONL records the original command and model prediction and describes the effective parse/planner outcome: production from `source_result`, raw rewrite from `generated_source_result`, and guarded outcome from guarded `source_result`. For guarded rows retained as `rules_accepted_or_other_terminal`, any parsing/planning defect belongs to the captured dev rule output, not the model.

## Confirmed semantic findings

- **Guarded fixes raw prediction errors:** T003 and T007 preserve the full quoted filename and target; T011 preserves `Archive-`; T018 preserves the ARCHIVE name filter; T021 preserves report→statement; T023 preserves the size/type filter and `2026-`; T088 preserves the `report` name filter and `Report-`. These are actual differences in operation arguments, even where fixtures produce no matches.
- **Raw regressions:** T022 rewrites removal of a word from filenames as trashing matching files. T028 omits “starting at 10” (planner starts at `scan-01`). T030 changes spaces-to-slashes into removal of spaces. T032 repeats `2026` where the command requests `2026, 2027`. T045 loses the second chained sort. T053 interprets “50 percent quality” as a 50 px resize. T064 merges only `report.pdf`, dropping `photo.jpg`. T066 silently changes invalid page 0 to page 1. T073 changes the extraction destination. T080 moves `Archive.zip` instead of zipping Archive as `.tar.gz`. T091 changes the replacement direction and corrupts the source literal. T099 omits sharpening; resizing by itself is supported, sharpening is not established by the command reference.
- **Refusal behavior:** T056/T065 request deleting originals after conversion/merge, and T075 requests password encryption; the typed hard refusals are appropriate safeguards for unsupported destructive/unsupported behavior. T085 mass-renames every file to one colliding name, T086/T087 chain an operation with zip/delete, and T095 asks for a conditional exception (“leave PDFs where they are”); refusal is safer than the raw partial rewrites. A refusal on T005/T012/T014/T019/T020/T025/T040/T054/T055/T076/T090 declines a documented supported action and is a model false refusal when raw is effective.
- **Planner scope matters:** A correct parsed intent can end in `problem` because a named folder/file is absent from the fixture (for example T025 Screenshots and T078 Backup.zip). This is not evidence that the operation is unsupported. Conversely, empty/no-match fixtures do not establish correctness or safety outside those fixtures. T096’s source is incorrectly interpreted as a file set and is blocked because folder `folder` is absent; that block does not repair the source-scope error.

## Comparison limits and evidence notes

The delta field is a qualitative comparison, not an accuracy measure. Corpus expectations are heuristic, production is an older parser/planner replay rather than gold truth, and model outputs are command rewrites, not runtime behavior. “Accepted” means parser acceptance; it does not establish intended operation. Planner actions are fixture-scoped. No application execution or installed-app integration was tested here.

The draft report describes the **earlier raw/guarded replay as using the last-built production executable** and says the parent corrected this with pinned binaries; that earlier directory is explicitly superseded. The active model raw `generated_source_result` and guarded `source_result` are the captured dev parser/planner results and are the evidence used here. Fresh-vs-existing replay discrepancies (T050/T051/T098 resize backup directory naming, plus other non-T rows) are documented in the draft/summary; they are not model semantic wins and should not be folded into a score. The summary’s 295/300 fresh-vs-existing match count is a rule replay consistency check, not model accuracy.
