# Tiny-model readiness work — 2026-11-16

The user authorized fixing the observed failures and getting the tiny model ready
for integration, with Luna subagents. This is new implementation work. Earlier
audit artifacts and model weights remain unchanged.

## Candidate hypothesis, fixed before new holdout evaluation

Keep tiny v3 as a command-rewrite model, but independently certify a bounded
subset of rewrites in Rust. Unknown or unsupported semantics remain refusals.
Exact literal values, argument roles, operations, filters and units must survive;
a null extracted schedule is not proof that schedule wording was preserved.
Recognized schedules belong to the scheduler and must not be generated by the
model. Accepted rules and typed hard refusals retain their existing priority.

Measure a compact quantized export of the unchanged checkpoint using actual
native local inference, with Python/native parity checks. Quantization or a
different runtime is a new candidate, not presumed equivalent to FP32.

## Readiness criteria

- Known 300-case failures become regressions; no wrongly accepted model additions
  or silent loss of literal names, constraints or requested operations.
- A new independently authored, frozen bank is excluded from implementation,
  training and guard tuning. Labels/schema are validated before inference.
- Zero confirmed accepted unsupported requests or file-changing misreads on the
  independent bank. Report baseline-rule errors separately; no overall accuracy
  claims from heuristic labels. Every accepted model addition is reviewed.
- Recover at least 10% of supported independent-bank commands refused by rules,
  with an explicit denominator and no changes to already accepted rule results.
- Model plus tokenizer/config payload at most 25,000,000 measured bytes. Record
  the native executable/runtime dependency size separately.
- Native single-sentence CPU p95 at most 200 ms after warmup, including model
  preprocessing and decoding. Report load time separately.
- Typed hard, scheduling/application and planner restrictions remain terminal;
  model output never executes directly. Previews and confirmation stay required.
- Reproducible model/source/runtime hashes, meaningful Rust regression tests,
  Python/native output comparisons, package/load/failure-path checks, and a Luna
  review of the implementation and final evidence.

If the untouched bank fails, do not relabel it, tune to it and call it untouched,
or relax these criteria. Further development requires a newly frozen independent
bank. Readiness is demonstrated by the evidence, not by completion of a workflow.

The deliverable is an integration-ready native candidate and documented API,
not an automatic production release or replacement of the installed app.
